# Claude-Codex 병렬 개발 워크플로

Claude Fable은 계획과 재계획만 맡고, Codex Sol/Terra는 구현과 검증을 맡는다. 오케스트레이터는 환경·범위·증거를 통제하고 모든 품질 게이트 통과 후 커밋한다.

## 시작 조건

- 모델을 임의로 대체하지 않는다. Fable 또는 지정된 Codex 모델을 사용할 수 없으면 실제 상태와 가능한 선택지를 보고하고 멈춘다.
- 사용자 목표, 제외 범위, 대상 저장소, 완료 조건을 먼저 고정한다. 범위를 바꾸는 추정은 하지 않는다.
- 기준 커밋, 브랜치, 기존 변경, 적용 지침, 도구 버전, 검증 명령을 기록한다. 비밀 값은 기록하지 않고 환경 변수 이름과 설정 유무만 공유한다.
- 기존 변경이 있으면 전용 worktree를 우선 사용한다. 그렇지 못하고 작업 파일과 겹치면 사용자 확인 전에는 수정·스테이징·커밋하지 않는다.
- 외부 정보성 사실이 필요하면 공식 문서만 사용한다. 시장 평가가 필요한 경우에만 사람들의 의견을 별도 의견 근거로 사용할 수 있다.

상세 산출물 형식과 실행 프롬프트는 [워크플로 계약](references/workflow-contract.md)을 따른다.

## `codex-handoff` 연동

시작할 때 다음 순서로 `codex-handoff/SKILL.md`를 찾는다.

1. 이 스킬의 형제 경로 `../codex-handoff/SKILL.md`
2. 대상 저장소의 `skills/codex-handoff/SKILL.md`
3. 사용자가 지정한 경로

존재하면 해당 `SKILL.md`와 작업에 필요한 연결 문서만 읽는다. 특히 `references/plan-format.md`의 태스크 형식과 `references/executor-protocol.md`의 범위·검증·센티널 규약을 재사용한다. 이 스킬은 그 위에 모델 분담, 환경 정렬, 병렬 웨이브, 차단 재계획, 독립 검증, 최종 커밋 게이트를 추가한다. 없으면 [워크플로 계약](references/workflow-contract.md)의 자체 형식을 사용하며 오류로 처리하지 않는다.

## 실행 순서

### 1. 환경 정렬

- Claude와 모든 Codex 세션에 동일한 절대 저장소 경로, 기준 커밋, 계획 파일, 사용자 목표, 적용 지침, 검증 명령을 전달한다.
- `CLAUDE.md`와 `AGENTS.md` 등 도구별 지침을 모두 확인해 공통 작업 브리프에 명시한다. 서로 모순되어 결과에 영향을 주면 임의로 우선순위를 만들지 말고 차단한다.
- 동일 checkout을 쓸 때는 쓰기 범위가 겹치지 않는 태스크만 병렬 실행한다. 겹칠 가능성이 있으면 같은 기준 커밋의 독립 worktree를 사용한다.
- 의존성 설치와 생성물 갱신은 한 담당자만 수행한다. lockfile, 마이그레이션, 공용 설정처럼 여러 태스크가 만지는 파일은 별도 순차 태스크로 분리한다.
- 정렬 결과가 다르면 계획 수립 전에 해결한다. 기준 커밋이나 필수 도구가 다른 상태로 실행하지 않는다.

### 2. Fable 계획

- Claude CLI를 대상 저장소에서 읽기 전용 계획 모드로 실행한다: `claude -p --model fable --permission-mode plan`.
- 저장소의 코드·설정·테스트를 근거로 계획하게 한다. Fable에는 구현 코드를 작성하거나 파일을 수정하지 말고 계획만 반환하도록 지시한다.
- 각 태스크에 목표, 의존성, 정확한 쓰기 범위, 검증 명령과 기대 결과, 구현 모델, 병렬 웨이브를 포함한다.
- 검증 명령이 없거나 쓰기 범위가 겹치는 태스크는 디스패치하지 않는다.

### 3. 계획 검토와 스케줄링

- 계획이 사용자 목표와 환경 스냅샷을 보존하는지 확인한다.
- 같은 웨이브에는 의존 관계가 없고 쓰기 범위가 서로 겹치지 않는 태스크만 둔다. 공용 파일과 통합 작업은 뒤의 순차 웨이브로 이동한다.
- 일반적인 국소 수정은 `gpt-5.6-sol`, 여러 모듈에 걸친 설계·마이그레이션·고난도 디버깅은 `gpt-5.6-terra`에 배정한다. 사용자 지정이 있으면 그것을 우선한다.

### 4. Codex 병렬 구현과 작업자 검증

- 사용 가능한 네이티브 다중 에이전트 기능을 우선 사용하고 각 작업자에 모델을 명시한다. 그렇지 않으면 별도 `codex exec -m <모델> -C <작업경로>` 세션을 병렬 실행한다.
- 작업자마다 태스크 하나, 쓰기 범위 하나, 기준 커밋 하나를 준다. 계획 변경, 다른 태스크 수행, 범위 밖 수정, 커밋을 금지한다.
- 작업자는 수정 후 자기 태스크의 검증 명령을 직접 실행하고 결과와 변경 파일을 보고한다.
- 공유 checkout에서는 작업자 검증 중 전체 테스트를 동시에 돌리지 않는다. 태스크별 검증만 실행하고 전체 검증은 웨이브 통합 후 한 번 실행한다.
- 전용 worktree 결과는 작업자가 커밋하지 않는다. 오케스트레이터가 허용된 diff만 통합 checkout에 적용하며, patch 충돌이나 범위 중첩이 생기면 자동 해결하지 않고 차단 절차로 보낸다.

### 5. 차단과 Fable 재계획

- 요구사항 모순, 계획 누락, 범위 충돌, 환경 불일치, 권한·의존성 부재, 검증 불가능을 발견하면 추정으로 우회하지 않는다.
- 작업자는 [차단 보고서](references/workflow-contract.md#차단-보고서)를 남기고 호환 센티널 `TASK_FAIL T<N>: BLOCKED <요약>`으로 종료한다. 독립적인 다른 태스크는 계속할 수 있다.
- 오케스트레이터는 차단 보고서, 관련 diff·로그, 현재 계획, 환경 스냅샷을 Fable에 제공해 계획 수정만 요청한다.
- 수정 계획이 사용자 목표·공개 인터페이스·의존성·데이터·보안 경계를 넓히면 사용자 승인을 받는다. 그 외에는 영향받은 미완료 태스크만 다시 스케줄한다.
- 같은 원인의 차단이 수정 계획 뒤에도 다시 발생하면 자동 재계획을 중단하고 사용자에게 판단을 요청한다.

### 6. Codex 독립 검증

- 각 웨이브 뒤 오케스트레이터가 `git diff`와 `git status --short -uall`로 범위 밖 변경과 누락 파일을 확인하고 전체 검증을 한 번 실행한다.
- 구현에 참여하지 않은 Codex 세션이 변경 없이 diff를 검토하고 검증 명령을 재실행한다. 가능하면 Sol 구현은 Terra가, Terra 구현은 Sol이 검증한다.
- 실패하면 커밋하지 않는다. 구현 오류는 해당 Codex 작업자에게 한 번 구체적으로 재지시하고, 계획 오류나 환경 오류는 차단 절차로 보낸다.

### 7. 최종 게이트와 커밋

다음이 모두 참일 때만 커밋한다.

- 모든 계획 태스크가 검증 증거와 함께 완료됐다.
- 미해결 차단과 범위 밖 변경이 없다.
- 태스크별 검증, 전체 검증, 독립 Codex 검증이 모두 통과했다.
- 최종 diff가 사용자 목표와 일치하고 비밀·임시 로그·불필요한 생성물을 포함하지 않는다.
- 기존 사용자 변경이 스테이징 대상에 섞이지 않았다.

`git add -A`나 포괄 glob을 쓰지 말고 확인된 파일만 명시적으로 스테이징한다. staged diff를 다시 확인한 뒤 논리적 단위로 로컬 커밋하고 커밋 해시와 검증 결과를 보고한다. 사용자가 별도로 요청하지 않으면 push, PR 생성, 배포는 하지 않는다.

## 종료 보고

계획 파일, 모델별 담당, 완료·차단 태스크, 검증 명령과 결과, 변경 파일, 커밋 해시를 짧게 보고한다. 커밋하지 못했다면 실패한 게이트와 보존된 작업 상태를 정확히 적는다.
