# codex-handoff: 인라인 핸드오프 루프

Claude는 계획·검증만 하고 코드 생성 토큰은 실행자 쪽 요금제로 넘긴다.

## 전제

- 계획 파일이 이 스킬의 `references/plan-format.md` 형식(각 태스크에
  `검증:` 줄)을 따른다. 없으면 먼저 계획을 그 형식으로 작성한다.
  `검증:` 없는 태스크는 넘기지 않는다.
- **실행자 규약은 대상 프로젝트에 설치하지 않는다.** 핸드오프 프롬프트에
  이 스킬의 `references/executor-protocol.md`에서 해당 모드 섹션 **전문을
  내장**한다 — 프로젝트 AGENTS.md를 오염시키지 않기 위한 규칙이다.

## 핸드오프 프롬프트 형식

```
다음 실행자 규약에 따라 docs/superpowers/plans/<파일>의 T<N>을 수행하라.
작업 범위는 <대상 경로>뿐이다. 그 외 파일은 절대 건드리지 마라.

<executor-protocol.md의 "너는 실행자다..." 줄 + 인라인 모드 섹션 전문>
```

## 루프 (미완료 태스크마다 순서대로)

1. **핸드오프**: Bash로 실행 (타임아웃 넉넉히, 예: 10분):

   ```bash
   timeout --signal=TERM --kill-after=10s 10m \
     codex exec --dangerously-bypass-approvals-and-sandbox -C <프로젝트경로> \
     "<핸드오프 프롬프트 (규약 내장)>" < /dev/null 2>&1 | tee <로그파일> | tail -5
   ```

   - **`< /dev/null` 필수.** 비대화형(파이프) 환경에서 stdin을 닫지 않으면
     codex exec가 "Reading additional input from stdin..."에서 **무한 블록**된다
     (2026-08-04 실측: 25분+ 무진척, 파일 생성 0건). `resume --last`도 동일.
   - `| tail`만 붙이면 블록 증상이 가려진다 — 반드시 `tee <로그파일>`로 중간
     출력을 남겨 멈춤을 진단 가능하게 한다.
   - npm install 등 패키지 설치는 오케스트레이터가 사전 수행하고 실행자에게는
     파일 작업만 넘기는 편이 진단·재시도에 유리하다.

   직전 태스크와 문맥이 이어지는 경우(같은 파일 연속 수정 등)에만
   `codex exec resume --last "..."` 사용. 기본은 태스크마다 새 세션.
   병렬 디스패치 시(파일 비겹침 태스크) 각 실행자에게는 자기 테스트 파일만
   검증시키고, 전체 테스트·typecheck는 배치 완료 후 오케스트레이터가 돌린다
   (동시 전체 테스트는 쓰다 만 파일을 읽어 오탐).

2. **판정**: 출력 마지막 줄의 `TASK_DONE T<N>` / `TASK_FAIL T<N>` 확인.
   센티널과 무관하게 다음을 직접 수행한다:
   - `git -C <프로젝트경로> diff` + `git status --short -uall` — 범위 밖
     수정이 없는지 훑기 (`-uall` 필수: 신규 디렉토리가 접혀 보이면 그 안의
     개별 파일 생성을 놓친다)
   - 태스크의 `검증:` 커맨드 직접 실행 — 기대 결과와 대조

3. **분기**:
   - 통과 → 계획 파일 체크박스 `[x]` 갱신, 커밋, 다음 태스크로.
   - 실패 → diff에서 본 문제를 구체적으로 지적하는 재지시 프롬프트로
     `codex exec resume --last` **1회만** 재시도. 재실패 시 루프를 멈추고
     현재 상태(diff 요약, 실패 사유)를 사용자에게 보고한다.
   - codex 비정상 종료/타임아웃 → stderr 요약 후 해당 태스크 미완료로
     두고 사용자에게 보고한다.

4. 전체 완료 후: 태스크별 결과 한 줄씩 요약 보고.

## 하지 말 것

- Claude가 직접 구현 코드를 작성하는 것 (검증·소규모 수정 지시는 가능)
- 태스크당 3회 이상 실행자 호출 (폭주 방지 상한)
- 대상 프로젝트의 AGENTS.md·규칙 파일에 실행자 규약을 심는 것
