# 순차 회의 절차 v0.2

## 흐름

```text
질문 + 사용자가 명시한 목적·제약·자원
  → A0: 자료 없이 의견 1개
  → B0: 자료 없이 독립 의견 1개
  → C0: 부족한 정보와 조사·측정 항목 피드백
  → A1: 조사·의견 보완
  → B1: A1 검토·추가 조사·반박
  → C1: 검증·보고서 갱신·다음 과제
  → A2 → B2 → C2 → … → C가 최종 보고서 작성
```

한 회차는 A→B→C다. 중간에 A를 다시 호출하거나 A·B가 동시에 수정하지 않는다. 각 역할은 자기 차례 안에서 필요한 여러 도구 호출을 할 수 있다.

## 초기 의견: A0·B0

전달하는 내용은 스킬, 결정 질문, 사용자에게서 이미 받은 목적·제약·자원, 담당 관점, 출력 경로다. 조사 자료와 공용 근거 묶음은 첫 의견 이후에 제공한다. B0에도 A0의 답변을 보여주지 않는다.

각자 다음을 짧게 제출한다.

- 핵심 의견 하나.
- 그렇게 생각하는 이유.
- 확인해야 할 가정과 정보를 알게 되면 의견을 바꿀 조건.

이 단계에서는 검색·환경 조사·측정을 하지 않는다. 모든 미검증 주장은 가설로 취급하며, 첫 의견을 정량 근거가 있는 권고로 평가하지 않는다.

## C0: 첫 피드백

C는 두 의견을 비교해 결정에 중요한 누락을 다음 형식으로 지정한다.

| 항목 | 내용 |
| --- | --- |
| 대상 | A/B의 어느 주장 또는 빠진 선택지를 검토하는가 |
| 부족한 정보 | 어떤 사실·수치·측정이 필요한가 |
| 결정 영향 | 확인 결과에 따라 무엇이 바뀌는가 |
| 확보 방법 | 공용 기록 조회, 공식 페이지, 코드·로그 확인, 직접 측정 등 |
| 담당 | 다음 회차의 A 또는 B |
| 완료 조건 | 필요한 범위·환경·단위·산출물 |

A와 B의 조사 범위를 나누고, B가 A의 결과를 이어 쓸 수 있게 배정한다. C0는 조사 계획을 만드는 단계다.

## 회차 n: A → B → C

| 차례 | 입력 | 수행 | 출력 |
| --- | --- | --- | --- |
| A_n | 직전 C 피드백, B의 직전 의견, 현재 공용 기록 | 기존 자료 조회, 배정된 공식 정보 수집·측정, B 검토, 자기 의견 수정 | 핵심 의견 1개, 새 근거·수치·계산, 반박, 미확인·정보 문제 |
| B_n | 같은 회차 A 결과, 직전 C 피드백, 갱신된 공용 기록 | A의 결과 재사용·원문 검토, 담당 조사·측정, 반박·보완 | 핵심 의견 1개, 추가 근거·계산, 수용·반박 이유, 미확인·정보 문제 |
| C_n | 같은 회차 A/B 결과와 그 근거 원문, 공용 문제 | 근거 부합·출처·계산·누적 자원 확인, 조사 누락·측정 누락 판정 | 정량 비교표와 보고서 초안, 해결·미해결 항목, 다음 담당·방법, 종료 판정 |

첫 회차 A1은 B0와 C0를 사용한다. 다음 회차 A2는 B1과 C1을 사용한다. B는 항상 같은 회차의 A를 읽는다.

A/B의 완료 결과를 실행 담당자가 공용 기록에 게시한 뒤 다음 역할을 호출한다. C의 중요한 정정도 게시하고 다음 A가 반영 여부를 확인하게 한다.

C는 원문 확인·재계산·핵심 측정 재현 같은 검증 도구를 사용할 수 있다. 필요한 신규 조사는 다음 A/B 차례에 배정한다. 같은 결과의 재인용을 독립 증거로 세지 않는다.

## 관점 후보

| 관점 | A의 우선순위 | B의 우선순위 |
| --- | --- | --- |
| 구조 | 단순성 | 필요한 확장성 |
| 데이터 | 활용의 유연성 | 정합성과 변경 규칙 |
| 자원 | 현재 비용 절감 | 미래 유지보수 비용 절감 |
| 기능 | 핵심 범위 집중 | 고객 합류·유지 |
| 방향 | 목적·대상의 일관성 | 환경 변화에 적응 |
| 성능 | 필수 성능 충족 | 대기 안내·부분 결과 등 경험 보완 |
| 서비스 | 쉬운 사용·제공 범위 | 경쟁 가치·익숙한 경험 |

안건에 맞는 관점을 A/B에 배정한다. 필수 제약은 두 역할 모두 지킨다. 초기 의견을 유지하려고 반대 증거를 숨기지 않는다.

## C의 검사 기준

- 현재 접근 가능한 공식 자료와 내부 기록을 실제로 확인했는가.
- 측정 가능한 핵심 항목을 직접 측정했거나, 측정하지 못한 구체적인 이유가 있는가.
- 숫자마다 원문·확인 시점·단위·환경·조건이 있고, 서로 비교 가능한가.
- 사실과 추정이 분리되고, 미확인이 실패·미실행으로 바뀌지 않았는가.
- 계산식과 전체 비용·시간 합계가 맞는가. 검증 뒤 남는 자원도 반영했는가.
- 사업성의 고객 관심·구매 의향·실제 결제와 비용 가정을 구분했는가.
- 결론을 바꾸는 추정값의 범위·분기 조건과, 아직 정하지 않은 사용자 우선순위를 드러냈는가.
- 앞선 피드백이 실제 근거·측정으로 해결됐는가. 계획만 다시 제시하지 않았는가.
- 실패를 판단 근거로 쓸 때 정상 조건과 대조하고, 사용 조건·환경 제약·구현 문제를 구분했는가.

### 정상 조건과의 대조 실험

C는 기능 부재·성능 부족·대안 탈락을 실패 결과로 판단하기 전에 다음을 확인한다.

1. 공식 문서·로컬 구현에서 정상 사용의 필수 입력·권한·설정·호출 형식을 확인하고, 실험에서 실제로 충족했는지 기록한다.
2. 같은 목표·환경·측정 범위에서 정상 경로와 원래 실패 경로를 실행한다. 원인 후보를 분리해 변경하고, 바뀐 요소를 남긴다. 필수 요구나 자원 상한을 완화해 성공으로 만들지 않는다.
3. 조회 0건이나 검증 실패도 알려진 정상 자료·유효한 질의로 대조한다. 도구 사용 오류와 실제 데이터 부재·기능 결함을 구분한다.
4. 양쪽 명령·입력·설정·종료 코드·수치·원시 결과를 연결해 원인을 판정한다. 정상 경로가 성공하면 원래 실패를 그 조건 밖으로 일반화하지 않는다.
5. 대조 불가 또는 원인 미확정이면 확인한 실패 조건까지만 보고한다. 현재 실행 가능한 핵심 대조가 남아 있으면 다음 A/B 차례에 배정하고, 실제 제약이 있으면 미확인·제약·결정 영향을 명시한다.

기록에는 대상 주장, 정상 조건을 정한 근거, 실패 조건, 변경 요소, 양쪽 결과·근거 ID, 원인 판단과 한계를 포함한다. 성공·실패 판정 기준은 실험 전에 정한다.

## 종료와 사용자 보고서

반복 상한과 시간·비용 예산은 시작 때 기록한다. 미지정된 값은 실행 담당자가 안건 규모에 맞춰 가정임을 밝혀 설정한다.

C1 이후 C가 자기 차례 끝에 다음 중 하나를 판정한다.

- **계속:** 확보 가능한 핵심 근거·측정이 남음. 다음 A/B에게 방법과 완료 조건을 배정한다.
- **보고서 완료:** 가능한 핵심 조사·측정과 판단에 필요한 정상 대조를 수행했고, 미확인과 추정의 영향이 정리돼 사용자가 비교·결정할 수 있음.
- **한계 보고:** 자원 상한 또는 실제 접근·실험 제약으로 더 진행하지 못함. 확보한 자료와 미확인·결론 영향을 표시한다.

회의 진행 판정과 사업 권고(진행·조건부 진행·보류·중단)는 구분한다. 사업 중단을 권고하는 보고서도 충분한 조사를 마쳤다면 완료될 수 있다.

C는 매 회차 보고서를 갱신한다. 최종 보고서는 질문·권고, 선택지별 수치 비교, 핵심 근거 최대 3개, 비용·시간·대가, 추정·민감도, 미확인과 영향, 재검토 조건을 제공한다. 수치와 핵심 판단에서 해당 원문·측정 기록으로 바로 연결되는 링크를 제공한다.
