# 순차 회의의 공용 기록과 PMT 연결

## 입력 범위와 기록 소유

A0·B0에는 질문과 명시된 사용자 조건만 전달한다. 공용 프로젝트 자료의 조회·재사용은 C0 피드백 이후 A1부터 시작한다. 재개 시에는 현재 차례를 복원하며, 이미 끝낸 최초 의견을 다시 만들지 않는다.

역할 에이전트는 자기 의견·조사·검증 파일만 작성한다. 실행 담당자 한 명이 C의 배정·판정에 따라 공용 기록·차례·PMT를 변경한다. 저장 경로를 실제로 확인한 뒤 다음 역할에 결과를 전달한다.

이 계약은 파일과 단일 실행 담당자로 운용하는 방식이다. 여러 실행 담당자의 동시 쓰기나 자동 알림 서버를 구현한 것으로 취급하지 않는다.

## 최소 기록

| 파일 | 필수 내용 |
| --- | --- |
| meeting.json | ID, 질문, 사용자 조건, 모델·effort, A/B 관점, 자원·반복 상한, 현재 단계·회차·다음 역할 |
| turns/initial-A.json, initial-B.json | 의견 1개, 이유, 미확인 가정, 수정 조건; kind=opinion, evidence_ids=[] |
| turns/initial-C.json | 첫 누락 목록, 필요한 수치·확보 방법·담당·완료 조건 |
| turns/round-N-A.json, -B.json | 의견 1개, 새로 확보·재사용한 근거, 계산, 반박·수용, 미해결 사항 |
| turns/round-N-C.json | 검증 결과, 정상·실패 대조 기록, 지적 해결 상태, 다음 조사 과제, 계속/보고서 완료/한계 보고 판정 |
| evidence-vN.json | 근거 ID/버전, 내용·유형, 출처, 확인 시점, 단위, 환경·조건, 검증 상태 |
| research.json | 프로젝트·질문·환경·버전·범위의 조사 키, 담당 차례, 상태, 결과 근거, 차단·재시도 조건 |
| issues.json | 대상 주장/근거, 문제·영향, 담당·상태, 정정 버전 |
| acknowledgements.json | 역할·차례, 확인한 근거·문제, 반영 여부와 이유 |
| report.md, decision.json | 정량 비교와 권고, 사용 근거, 미확인·추정, 사용자 승인 여부 |

최초 A/B 입력의 근거 묶음은 비어 있다. 이후 각 차례에는 읽은 근거 버전과 게시한 새 버전을 기록한다. 근거 스냅샷은 덮어쓰지 않는다.

C의 피드백 항목마다 ID를 붙이고 조사 결과·측정 또는 차단 사유에 연결한다. 지적이 대화에만 있고 등록되지 않았다면 공유 완료로 표시하지 않는다.

실패를 근거로 판정하는 C 출력에는 control_experiments를 기록한다. 각 항목에 대상 주장, 정상 조건과 그 근거, 실패 조건, 변경 요소, 정상·실패 결과의 근거 ID, 원인 판단·한계를 둔다. 대조 불가는 사유와 후속 담당을 명시하며, 빈 기록을 검증 완료로 간주하지 않는다.

## 차례와 조사 재사용

- 허용 순서는 A0→B0→C0→A1→B1→C1→A2→B2→C2…다. 출력 저장과 공용 기록 게시가 끝나야 다음 역할로 전이한다.
- 최초 A/B는 서로의 의견을 읽지 않는다. A_n은 직전 B/C, B_n은 같은 회차 A, C_n은 같은 회차 A/B를 읽는다.
- 조사 전에 공용 결과와 진행 중 키를 조회한다. B는 A가 방금 확보한 결과도 조회해 같은 조사를 반복하지 않는다.
- 서로 다른 표현의 동일 질문은 실행 담당자가 의미와 적용 범위를 비교해 한 항목으로 연결한다.
- 측정 조건·환경·버전 변경은 별도 갱신 조사로, 의도적인 독립 검증은 목적을 명시한 검증 작업으로 등록한다.
- 실패·접근 불가에도 시도한 방법과 재시도 조건을 남긴다. ‘나중에 조사’만으로 완료 처리하지 않는다.
- 구체적인 차단이 없는데 근거가 계속 추가되지 않으면 C가 다음 담당이나 확보 방법을 바꾼다.

## proj-mgmt-tool-v2 연결

연결할 때 해당 SKILL.md를 먼저 읽고 실제 경로로 호출한다. 없으면 위 파일 계약으로 운영하고 PMT 연결 부재를 기록한다.

- 기존 프로젝트는 resume으로 재개한다. 새 프로젝트는 사용자가 허용한 데이터 루트에 생성한다.
- 실행 담당자만 start·note·verify·end와 PMT 문서·lock을 변경한다. C는 검증 판단을 자기 출력에 남기고 실행 담당자가 게시한다.
- Work/Item은 회의·조사 작업에 연결한다. 상세 기록은 프로젝트 resources/evidence에 두고 fact·backlog·note에서 참조한다.
- 동일 질문을 다른 Item으로 등록하면 PMT 잠금만으로 중복을 막지 못하므로 조사 키도 확인한다.
- PMT fact의 Active/Closed와 근거의 확인됨/충돌/재확인 필요는 별도 상태다.
- AI 권고는 사용자 승인 전까지 evidence 또는 backlog에 남긴다. decide는 사용자 승인 후에만 사용한다.
- 같은 PMT session의 하위 에이전트를 독립 잠금 소유자로 취급하지 않는다.
- 프로젝트 도구의 동작과 보고서의 근거 품질은 따로 검증한다.

프로젝트·자료 권한과 민감 정보 정책은 유지한다. 새 작업의 과도한 지출·배포·삭제 권한을 토론 참여 자체에서 추론하지 않는다.
